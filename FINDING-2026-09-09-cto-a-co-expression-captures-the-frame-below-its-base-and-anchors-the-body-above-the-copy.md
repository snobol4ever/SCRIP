# FINDING 2026-09-09 (cto) — a co-expression captures the frame BELOW its base and anchors the body ABOVE the copy: R1 and R2 are one instruction's constant and one register

Row: `icon-coexpression-capture-base-register-r2-rides-the-zeta-cut` (CEO-460/461/462; hq_S's brief FINDING-2026-09-09-hq_S-a-co-expression-body-reads-enclosing-locals-out-of-bounds-below-its-frame-snapshot.md; the coo's R1/R3 storage row absorbed per CEO-462).

## The mechanism, as hq_S measured it and the derivation confirms

An Icon host's prologue carves its activation at the call: `rax` = the new spine top, `lea rbp, [rax + frame_total]`, so the parameters and locals live in the `frame_total` bytes BELOW `rbp` and the four housekeeping words (caller rbp, γ, ω, the caller's pre-entry rsp) sit at `rbp+0..+24`. `bb_create` saved `contract_regs[5]` as `rsp` when the host was not pinned and `rbp` when it was, and `scrip_coexpr_create` copied `frame_total` bytes UPWARD from that register and anchored the body's `rbp` at the copy's first byte. With `rsp` saved (hq_S's build: the host was not a pinned host before the derivation) the copied range started wherever the spine happened to be and the body read `[cp - k]`, below the malloc'd block, for every parameter and local. With `rbp` saved (every host that contains a `create` is a window host under the derivation, so it pins itself) the range `[rbp, rbp + frame_total)` is the housekeeping and the caller's frames -- the locals are still not in the copy, and `[cp - k]` is still out of bounds.

## The cure, in one register and one constant, plus the trampoline that had to learn it

The base register is the DERIVED tier's frame base, not the host-epilogue predicate: `bb_create` saves `rbp` whenever the cells graph's derived tier is pinned -- which includes a GENERATOR host, whose N-3 prologue also sets `rbp` at `rax + frame_total` and whose body addresses off it, yet which `icn_host_pinned()` excludes for its epilogue's sake (hq_S's witness host is a generator: that is why their build saved `rsp`). `bb_create` passes a fourth argument, the below-extent, which IS the prologue's own `frame_total` (`_.flat_carve_total`, the constant of the host's `lea rbp,[rax+N]`, now recorded by the generator prologue too) for a pinned host and 0 otherwise; `scrip_coexpr_create(body, regs, above, below)` copies `[regs[5] - below, regs[5] + above)` and anchors the body at `cp + below`, carrying `below` in the entry package and `frame_copy_below` on the context so `^c` reproduces it (refresh reconstructs the base as `csav5 + below`); the GC root range covers the whole span. AND THE TRAMPOLINE: `scrip_coexpr_trampoline_entry` does not run the body on the malloc'd copy -- it copies `frame_bytes` from the anchor onto the co-expression's OWN stack and sets `rbp` to that copy's first byte, so an anchor at `cp + below` merely copied the above half (measured: the witness stayed null with the extent correctly passed as 624). The package now carries the whole span from `cp` and the trampoline adds `below` to `rbp` after the copy. hq_S built exactly this shape and withdrew it because `below` computed to 0 from the varslot table; the varslot table carries no negative offsets because the locals' extent is not a slot quantity, it is the prologue's carve constant, which the derivation's host pin now makes the base register's own.
